# Implementation Report: N4.5 runs the hook in the target's environment and halts when it fails (#3705, #3706)

## What was wrong

`assemblyzero/workflows/testing/nodes/mechanical_hooks.py` (N4.5, #3678) ran the target's `post_implement_command` with the workflow's own environment, so a hook of the form `poetry run python -m <package>` ran AssemblyZero's interpreter and failed with `ModuleNotFoundError` (#3705). The failure, an unreadable `.unleashed.json`, and a subprocess exception were each logged as `[WARN]` and the run proceeded to the green phase; two of those paths carried `# fail-open:` tags that the operator's rule of 2026-09-25 (#3585) had withdrawn (#3706).

## Changes made

1. `hook_environment()`: the hook's environment is the workflow's minus `VIRTUAL_ENV`, `POETRY_ACTIVE`, and that virtualenv's `bin`/`Scripts` entry on `PATH`, the way #1415 fixed `tools/dependabot_review.py`. The caller's mapping is not mutated.
2. A non-zero hook exit, an unreadable config, or a hook that cannot start returns `error_message` with the command, the exit code and the stderr (or stdout), and `route_after_mechanical_hooks` in `graph.py` sends it to HALT. The unconditional N4.5 to N5 edge became a conditional one. Both `# fail-open:` tags are gone; hook stdout and stderr go to the gate log on success and failure alike.
3. `atlas.py`: N4.5's successors name HALT.
4. `core/gate_registry.py`: row `impl.build_hook_failed` (judges infrastructure, halts) for the new site, `created_by="#3706"`, with the ruling that raised the ratchet named in its notes; `tests/fixtures/gate_registry_baseline.json` regenerated by `tools/audit_halt_sites.py --write-baseline` (impl halt rows 33 to 34).
5. `tests/fixtures/fail_open_baseline.json` regenerated by `tools/audit_fail_open.py --write-baseline` (two declared sites gone).

## Not changed

The `git add .` after a successful hook stays as #3678 wrote it.
