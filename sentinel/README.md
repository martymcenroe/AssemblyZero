# pr-sentinel

PR Issue-Reference Enforcer — a GitHub App on Cloudflare Workers.

Every PR must reference an open issue (`Closes #N`) or declare `No-Issue: <reason>`. The app creates a check run that blocks merge until the requirement is met.

> **This directory is the deployed source.** `martymcenroe/sentinel` is a separate public repository containing an earlier, weaker copy of this code — no `verify-issues.js`, and dependabot PRs skipped without posting a check. Both declare `name = "pr-sentinel"` in their `wrangler.toml`, so either could overwrite the live Worker. This tree is the one that is actually running, proven 2026-07-30 by inspecting the deployed bundle (AZ #1972). Make changes here.

## Secrets (Wrangler)

The worker expects three secrets (set via `wrangler secret put`):

- `WEBHOOK_SECRET` — GitHub webhook HMAC secret
- `APP_ID` — GitHub App ID
- `PRIVATE_KEY_B64` — Base64-encoded PKCS#8 private key

## Branch Protection

`scripts/set-branch-protection.sh` batch-applies the required status check to all repos for the configured owners.

```bash
# Dry run (shows what would change)
./scripts/set-branch-protection.sh --dry-run --owner martymcenroe

# Apply
./scripts/set-branch-protection.sh --owner martymcenroe
```

## Architecture

```
src/
  index.js          — Entry point: /health and /webhook routes
  webhook.js        — HMAC-SHA256 signature verification + event dispatch
  auth.js           — GitHub App JWT generation + installation token exchange
  checks.js         — GitHub Checks API (create check runs)
  validate.js       — PR body regex validation (issue refs, No-Issue exemption)
  verify-issues.js  — Verify referenced issues exist and are open (not PRs, not closed)
```

## CI deploy

Connected to Cloudflare Workers Builds 2026-07-30 (AZ #1974). A push to `main` that touches `sentinel/` runs the test suite and, if it passes, deploys.

| Setting | Value |
|---|---|
| Repository / branch | `martymcenroe/AssemblyZero` / `main` |
| Root directory | `/sentinel` |
| Build command | `npm test` |
| Deploy command | `npx wrangler deploy` |
| Build watch paths | `sentinel/*` |
| Non-production branch builds | disabled |
| Build caching | enabled |
| API token | auto-generated by Cloudflare |

**`npm test` as the build command is the only automated gate on this code.** AssemblyZero's `ci.yml` is Python-only — it runs pytest and never invokes vitest — so nothing else in CI executes these 58 tests. A failing test fails the build and nothing deploys.

Before this connection the Worker was deployed by hand, and the live version had been published 18 seconds *before* its source was committed — for that window the running artifact existed in no commit anywhere. That is what made "which source is deployed?" unanswerable and produced AZ #1972.

Setup and troubleshooting: `docs/runbooks/0951-pr-sentinel-ci-deploy.md`.

### Verifying what is actually deployed

Manual deploys are still possible, so the repo is not proof of what is running. To check, read the Worker rather than the tree:

```bash
npx wrangler deployments list      # from this directory
npx wrangler versions list
```

or fetch the deployed bundle through the Cloudflare API. While Workers Builds stays connected, drift self-heals on the next qualifying push to `main`; if it is ever disconnected, that guarantee disappears.
